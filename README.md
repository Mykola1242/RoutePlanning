# RoutePlanning

Прототип інформаційної системи підтримки виконання місій мобільної робототехнічної платформи.

## Що працює

- Вибір складу: «Північний» 24 × 16 або «Східний» 48 × 32, масштабування й прокрутка карти.
- Вибір довільної вільної цілі або станції.
- A* із NetworkX: чотири напрямки, ціна кроку 1, мангеттенська евристика.
- Покроковий рух, пауза, продовження, зміна швидкості й скидання.
- Додавання та видалення палет, автоматичне перепланування вже побудованого маршруту.
- Обробка недоступної цілі; журнал подій і вимірювання часу планування.

## Запуск у Windows

Потрібен Python 3.11+. Для зміни/перезбирання інтерфейсу — Node.js 22.13+ та npm.
У терміналі в корені проєкту:

```powershell
.\start.ps1
```

Якщо політика PowerShell блокує сценарії, виконайте команди окремо:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-lock.txt
cd frontend
npm.cmd ci --cache .npm-cache
npm.cmd run build
cd ..
.\.venv\Scripts\python.exe main.py
```

Відкрийте http://127.0.0.1:8000. Зупинка сервера — Ctrl+C.
Після першого налаштування достатньо запускати `main.py` інтерпретатором `.venv`.

## Спробуйте

1. Натисніть «Відвантаження», потім «Побудувати маршрут».
2. Натисніть «Запустити».
3. Оберіть інструмент «Перешкода» та клікніть на маршрут попереду робота.
4. Побачите обхід і запис про перерахунок у журналі.
5. Спробуйте паузу, іншу ціль та скидання.

## Будова

- `backend/simulation.py` — модель складу, стан симуляції, NetworkX A*, рух та події.
- `backend/app.py` — FastAPI, окремі сесії браузера та роздача зібраного інтерфейсу.
- `frontend/src/main.jsx` — React, карта SVG, панель керування та журнал.
- `frontend/src/style.css` — адаптивний інтерфейс.
- `main.py` — запуск локального сервера.
- `tests/` — перевірки маршрутів незалежним BFS, руху, перепланування та API.

Стан робота змінює Python. Браузер надсилає команди й запити кроку із заданою частотою.
Симуляція сповільнюється при обмеженні таймерів неактивної вкладки; фізичного часу тут немає.
Кожне відкриття сторінки створює нову сесію. Стан не зберігається після перезапуску сервера.
Неактивні сесії прибираються під час створення нової після 2 годин простою.

## Рухомі перешкоди (v0.2)

Над картою є інструменти «Візок ↔» і «Візок ↕». Клік додає фіолетовий візок
із горизонтальним або вертикальним патрулюванням; клік по візку цим інструментом прибирає його.
Візки можна додавати до запуску та під час виконання маршруту. Вони рухаються лише
під час активної симуляції, включно з очікуванням робота. Пауза заморожує весь світ.

За такт кожний візок проходить одну клітинку, розвертаючись біля меж, стелажів і палет.
Візок не займає поточну клітинку робота або іншого візка. Після руху візків робот
перевіряє решту маршруту; при блокуванні повторює A*. Якщо шляху немає, він чекає
й повторює пошук на наступних тактах. При появі шляху рух відновлюється автоматично.

Приклад: після скидання виберіть «Відвантаження», побудуйте маршрут, додайте
вертикальний візок у клітинку (8, 13) та натисніть «Запустити». Уже на першому такті
візок перетне початковий маршрут у (8, 14) і спричинить перепланування.

Це дискретна реактивна модель із повним знанням карти, без прогнозу траєкторій,
сенсорів і фізики. Візки можуть чекати один на одного; уникнення взаємних заторів
та гарантія завершення місії за будь-якого руху перешкод не реалізовані.

## Автономний бот доставки (v0.3)

Кнопка «Додати бота доставки» створює синього бота B у клітинці (2, 7).
Він сам будує A* до станцій у циклі: приймання → пакування → відвантаження.
Синій пунктир — його маршрут. На кожній станції він обслуговується три такти.
Панель показує його ціль, стан, очікування та число обслужених станцій.

«Запустити без місії R-01» запускає середовище окремо; повторне натискання його зупиняє.
Під час місії R-01 бот також рухається. Якщо окремий запуск середовища вимкнений,
завершення місії R-01 зупиняє й бота. Загальна пауза зупиняє всю симуляцію.

Поточна й наступна запланована клітинки R-01 зарезервовані для нього. Бот не входить
у них або в клітинки інших візків. При тимчасовому блокуванні чекає три такти,
після цього шукає обхід. Нова палета на його шляху викликає перепланування відразу.
При повній недоступності цілі він чекає й повторює пошук. Гарантії відсутності
заторів у довільному середовищі немає: це локальні правила, не спільний планувальник
руху всіх учасників. Деталі реалізації — `backend/delivery_bot.py`.

## Межі поточної версії

Це основа для диплома, а не завершена агентна система. Черги місій,
комп'ютерного зору, фізики та моделювання сенсорів поки немає.
Робот займає одну клітинку, карту знає повністю. Зміни від оператора відомі відразу.
Палети нерухомі; кожна ручна зміна після планування запускає повний A* заново.
Для рухомих візків пошук запускається при перекритті маршруту або під час очікування.
Прогрес місії показує частку завершених завдань; для ручного маршруту — співвідношення
пройдених і поточних залишкових кроків. Після додавання етапу або об'їзду він може зменшитися.
Довжина та час симуляції умовні. Замір планування включає побудову графа.
Сервер призначено для локальної демонстрації, він слухає лише 127.0.0.1.

Наступні етапи: відтворювані експерименти → розширення сценаріїв місій → підключення 3D-симулятора.

## Місії з текстових команд (v0.4)

У корені проєкту (поруч із `main.py`) є локальний `.env`. Вставте свій ключ після `=`:

```dotenv
OPENROUTER_API_KEY=ваш_ключ_OpenRouter
OPENROUTER_MODEL=anthropic/claude-haiku-5.5
```

Якщо `.env` відсутній після копіювання проєкту, скопіюйте `.env.example` у `.env`.
Файл читається за абсолютним шляхом від бекенду, незалежно від робочої папки IDE.
Підтримуються прості рядки `KEY=value`, необов'язкові лапки й коментарі на окремих рядках;
інтерполяція та багаторядкові значення не підтримуються. Змінні середовища процесу
мають пріоритет. Ключ ніколи не повертається браузеру; `.env` виключений із Git.
Не додавайте ключ у React, скриншоти, архіви чи повідомлення.

1. Запустіть `main.py` через `.venv` і відкрийте http://127.0.0.1:8000.
2. Якщо сервер працював до оновлення — перезапустіть його, у браузері натисніть Ctrl+F5.
3. У верхній правій панелі натисніть «Перевірити ключ у налаштуваннях», якщо ключ щойно додано.
   Це тільки перевірка наявності ключа, без запиту до провайдера; валідність перевіриться під час планування.
4. Введіть: «Забери вантаж із приймання, достав на пакування та повернися на базу».
5. Натисніть «Скласти план». Перевірте дії, потім «Запустити місію».
6. Можна додавати перешкоди й візки під час руху, призупиняти або скасовувати місію.
   Якщо прохід повністю перекритий нерухомими перешкодами, звільніть його й натисніть «Продовжити місію».

LLM отримує лише команду (до 1500 символів), короткі правила й стан робота/станцій.
У відповідь потрібна JSON-схема з діями `go_to`, `load`, `unload` або уточненням/відмовою.
Для уточнення доповніть початковий текст і знову складіть план: історія чату не зберігається.
Python перевіряє ідентифікатори станцій, доступність маршруту через нерухомі перешкоди,
послідовність дій, положення робота та стан вантажу. Перед запуском перевірка повторюється.
Зміна складу під час запиту робить відповідь застарілою, і вона не застосовується.

Виконавець підтримує одну місію до 16 кроків, один умовний вантаж без номенклатури
та кількісного обліку. Завантаження/розвантаження займають по три такти на будь-якій
робочій станції, але не на базі. Скасування зберігає вже завантажений вантаж;
перерване завантаження ще не додає вантаж. Скидання повністю очищає симуляцію.
Довільна ручна ціль недоступна, поки є незавершена місія — спочатку скасуйте її.

Економія: один API-запит на натискання, максимум 1200 вихідних токенів,
reasoning вимкнено, автоматичних повторів немає. Один запит одночасно на сервер,
між запитами щонайменше три секунди; тайм-аут читання відповіді 30 с.
Інтерфейс показує час відповіді, токени й вартість, якщо OpenRouter її повернув.
Обмеження витрат ключа задається в OpenRouter; локальний ліміт доларів не реалізований.
Кроки руху, A* та перепланування не звертаються до моделі.

Це LLM-планувальник місій із детермінованим виконавцем. Реакцію LLM на тривале
блокування додано у v0.5 (нижче). MCP не підключений. Бот B залишається окремим програмним контролером.
Без ключа ручні маршрути та бот працюють, а кнопка створення LLM-плану недоступна.

Код: `backend/planner.py` — API OpenRouter, `backend/missions.py` — контракт і перевірки,
`backend/simulation.py` — виконання, `frontend/src/MissionPanel.jsx` — панель місії.
Тести в `tests/test_missions.py` використовують підставні відповіді провайдера,
не звертаються до платного API й не доводять мовну точність моделі.

## Реакція агента на блокування (v0.5)

Звичайний обхід перешкоди виконує A* без LLM. Якщо в активній місії немає
доступного шляху до поточної станції протягом **6 тактів**, симуляція призупиняється
й звертається до тієї самої моделі через OpenRouter. Це такти симуляції, не секунди:
при 2 кроках/с поріг приблизно 3 секунди. Як і рух, автоматичні перевірки запускаються
відкритим інтерфейсом; прихована вкладка може сповільнювати таймери.

Python передає агенту стан вантажу, поточну станцію, залишок завдань, результат
перевірки доступності зі статичними/динамічними перешкодами та перелік дозволених дій.
Повна карта, історія чату й секрети не передаються. Агент повертає одну дію й коротке
пояснення, а виконавець повторно перевіряє умови:

- **Почекати** — до 8 тактів; середовище рухається й маршрут перевіряється локально.
  Доступно лише один раз за інцидент. Якщо шлях відкрився, місія продовжується без другого запиту.
- **Повторити маршрут** — тільки якщо Python підтвердив доступність поточної цілі.
- **Звернутися до оператора** — пауза, пояснення, ручне продовження або скасування.
- **Від’їхати на базу** — лише з прапорцем-дозволом, установленим у плані до запуску,
  при тимчасовому блокуванні та доступній базі. Перед поточним завданням вставляється
  один `go_to base`; решта дій, їхній порядок і вантаж зберігаються. Максимум один
  такий від’їзд за місію, він не гарантує, що станція звільниться до повернення.

Ліміти: максимум **2 звернення за інцидент і 3 за місію**, до 400 вихідних токенів
на рішення, reasoning вимкнено. Повтор одного квитка інциденту не робить нового
запиту. Ці ліміти додаткові до одного запиту створення плану; ручне продовження
не скидає лічильник. Новий план/повне скидання створює новий бюджет. Це обмеження
кількості спроб, а не гарантована доларова квота. Після помилки API або вичерпання
ліміту — пауза для оператора, без автоматичних повторів.

Під час відповіді моделі можна скасувати місію, натиснути «Зупинити й вирішити вручну»
або змінити карту. Запізніле рішення не перезаписує ці зміни. Панель показує стан
інциденту, число звернень і історію рішень із токенами/вартістю, якщо їх надав провайдер.
Короткі блокування усуваються автоматично; після звернення до оператора потрібне
явне «Продовжити місію» навіть після звільнення проходу.

### Сценарій для демонстрації

1. Створіть і запустіть місію «Забери вантаж із приймання й достав на пакування».
2. Поки робот їде на приймання, виберіть «Перешкода» і поставте палету на станцію
   пакування **(22, 7)**. Це майбутня, ще не поточна ціль.
3. Після завантаження робот не зможе побудувати маршрут до пакування.
4. Через 6 тактів з’явиться пояснення агента. Для нерухомої палети очікується
   звернення до оператора; якщо модель спершу обере очікування, воно обмежене 8 тактами.
5. Приберіть палету кліком у (22, 7), натисніть «Продовжити місію» й дочекайтеся доставки.

Новий код: `backend/recovery.py` — виявлення інциденту, дозволи, перевірки та застосування
дій; `backend/planner.py` — окремий короткий запит рішення; `POST /api/sessions/{id}/recovery`
— обробка без блокування команд оператора. Тести `tests/test_recovery.py` перевіряють
ліміти, збереження вантажу, заборонені дії, гонки відповідей і завершення після усунення проблеми.

## Дві карти (v0.6)

Над картою є список **«Карта складу»**:

- **Склад «Північний»** — збережена карта 24 × 16, 6 стелажів, 3 робочі станції й база.
- **Логістичний центр «Східний»** — 48 × 32, 24 стелажі, два приймання, два пакування,
  відвантаження й база. Проходи різної ширини та поперечні коридори дають альтернативні маршрути.

Перемикання призупиняє попередню симуляцію та відкриває нову, з чистою картою й новою
місією. Повернення до іншої карти не відновлює попередній прогрес. Кнопка скидання
очищає поточну симуляцію, але зберігає вибір складу. Після перезавантаження сторінки
за замовчуванням відкривається «Північний». Для збільшення клітинок виберіть масштаб
150% або 200%; область карти прокручується горизонтально й вертикально.

Приклад місії на великій карті:

> Забери вантаж із приймання №2, достав на пакування №2 та повернися на базу.

Станції «Східного»: приймання №1 (2, 3), приймання №2 (2, 20), пакування №1 (45, 8),
пакування №2 (45, 22), відвантаження (45, 29); база (2, 29). Цифри на карті — порядкові
номери всіх робочих станцій, тому пакування №2 позначене маркером **4**.

Модель отримує лише станції поточної карти. На великому складі вказуйте номер станції;
для неоднозначного «на пакування» модель має уточнити номер. Явний дозвіл «на будь-яке
пакування» дозволяє вибрати станцію під час складання плану. Автоматична заміна станції
доставки під час виконання не додавалася: агент зберігає узгоджені завдання.
На обох картах працюють A*, візки, бот доставки, вантаж і реакція агента на блокування.
Бот послідовно патрулює всі робочі станції обраного складу.

Макети винесені в `backend/maps.py`. `GET /api/maps` повертає каталог,
`POST /api/sessions?map_id=hub` створює великий склад, `map_id=north` — початковий.
Без параметра використовується початковий склад. Власні координати, стелажі, база
та станції кожної сесії використовуються у валідації місій, маршрутизації й рішеннях агента.

## Використані компоненти

- React та Vite — інтерфейс і збірка.
- FastAPI та Uvicorn — локальний сервер.
- NetworkX — готова реалізація A*: https://networkx.org/documentation/stable/reference/algorithms/generated/networkx.algorithms.shortest_paths.astar.astar_path.html
- Lucide — піктограми.

Реалізація A* належить бібліотеці NetworkX. Власний код: інтеграція, модель симуляції,
керування станами, перепланування, API та інтерфейс.

## Форматування фронтенду

У папці `frontend` виконайте `npm.cmd run format`. Перевірка стилю — `npm.cmd run format:check`. Налаштування Prettier містяться в `.prettierrc.json`. Редагуйте файли в `src`, а не згенеровані файли в `dist`.
